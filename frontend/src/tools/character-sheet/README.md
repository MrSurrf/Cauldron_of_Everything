# Инструмент «Лист персонажа»

Самостоятельный workspace-инструмент с публичной точкой входа `index.ts`.

- `model/` содержит сериализуемый документ, reducer, ruleset и безопасный
  формульный движок.
- `ui/` содержит внутренние предметные компоненты листа.
- `manifest.ts` описывает будущую плитку Workspace без привязки к runtime UI.
- Storybook является текущим host для разработки инструмента.

Desktop-композиция имеет фиксированную ширину `60.25rem` (`61rem` вместе с
внешними отступами) и построена по постоянным пропорциям классического листа:
узкая шкала характеристик, колонка проверок, широкая боевая область и колонка
заметок. Лист не перестраивается вслед за workspace или viewport. На узком
экране общий `ScrollArea` предоставляет горизонтальную и вертикальную прокрутку,
а длинные коллекции сохраняют собственную внутреннюю прокрутку.

В редакторе экземпляра «Моего стола» высота области листа ограничена рабочим
окном. Host включает `fitWidth`: лист целиком уменьшается под ширину viewport
через `zoom` страницы, а исходная геометрия, поля и документ не меняются.
Масштаб пересчитывается при resize панели; лист никогда не увеличивается больше 100%.
Вертикальная прокрутка остаётся общим `ScrollArea`, его органы управления не масштабируются.
Без `fitWidth` сохраняется исходная ширина и прокрутка в обе стороны.

Лист начинается с основных сведений о персонаже: верхняя панель «Лист
персонажа» и UI настройки шрифтов/плотности удалены во всех host-окружениях.
Данные оформления старых документов читаются для совместимости; элементы
управления игровыми полями и ресурсами сохранены.

Оформление использует общие токены проекта с насыщенными фиолетовыми
акцентами и тонированными поверхностями. У секций и карточек
оставлен один внешний контур без вложенных декоративных рамок и светящихся
полос. Рамки редактируемых полей и подсветка фокуса сохранены. Общий материал
крупных панелей подключён только к внешней оболочке листа. У шапки с именем
и основными сведениями скрыты внешняя рамка и фоновая подложка.

`CharacterSheetTool` поддерживает два режима данных:

- `initialDocument` создаёт автономный редактируемый экземпляр;
- `document` + `onDocumentChange` образуют controlled-контракт для repository,
  автосохранения и будущей загрузки из Django API.

Настройки плитки хранят только `characterId` (`CharacterSheetTileSettings`),
поэтому несколько workspace-плиток могут ссылаться на один документ, не
дублируя его в layout.

Инструмент не импортирует другие tools и не обращается к backend. Запись
инвентаря хранит `itemId` и данные экземпляра, а не копию предмета
Encyclopedia.

Формулы разбираются собственным tokenizer/parser в AST и вычисляются без
`eval`/`Function`. Реестр переменных ruleset расширяется пользовательскими
ключами только после проверки синтаксиса, уникальности и конфликтов с
системными переменными.

Большие текстовые разделы используют общий shared `ContentEditor`. Пользователь
всегда видит оформленный текст без Markdown-маркеров; при выделении появляется
контекстное форматирование, а в пустом абзаце — меню структурных блоков. Обе
панели рендерятся поверх layout и не меняют размеры секции. Совместимый строковый
codec пока сохраняет `[[roll:2d6+3]]`, `:::resource[...]` и
`:::collapsible[...]` только как внутренний формат данных. Броски вычисляются
ограниченным dice-parser без `eval`. Личностные разделы внизу колонки заметок
сворачиваются, освобождая место разделу особенностей внутри фиксированной рамки
листа; остальные обычные секции не сворачиваются.
