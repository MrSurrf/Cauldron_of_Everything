# Редактор статей

`/articles/create` открывается кнопкой «Создать статью» в каталоге. Тонкая страница
находится в `pages/articles`, реализация — здесь; зависимости от других инструментов нет.

## Первый этап: только браузер

Черновики автоматически сохраняются в IndexedDB с задержкой 450 мс; переключение,
кнопка сохранения, уход со страницы и сворачивание вкладки запускают запись сразу.
Фотографии хранятся отдельными Blob, а не base64 внутри текста. При ошибке сохранения
правки остаются в памяти вкладки, доступна повторная попытка. Принудительное закрытие
браузера не позволяет гарантировать завершение асинхронной записи; ориентируйтесь на
статус «Сохранено в этом браузере». Очистка данных сайта удаляет локальные статьи.

Данные разделены по локальному идентификатору аккаунта (это не механизм авторизации).
Подробнее об очереди, повреждённых данных, параллельных вкладках и неиспользуемых
оригиналах — в [model/README.md](./model/README.md).

`scheduledFor` — желаемое время **отправки на модерацию**, ISO UTC. Интерфейс вводит
и показывает его в часовом поясе браузера. Значение хранится в черновике, но не создаёт
таймер или фоновое задание и не изменяет статус на «отправлено». Кнопка реальной
отправки отключена до подключения API.

## Markdown и фотографии

Предпросмотр использует `react-markdown` + `remark-gfm`: заголовки, цитаты, списки,
таблицы, ссылки, код и зачёркивание. Произвольный HTML не исполняется; точные пары
`<u>…</u>` панели инструментов поддержаны отдельно без разрешения HTML-атрибутов.

- Локальная фотография: `![Описание](article-image:<uuid изображения>)`.
- Отдельная карточка: `[Название](entity:<числовой id энциклопедии>)` на отдельной строке.
- Такая же ссылка внутри абзаца отображается компактной ссылкой на энциклопедию.

Карточки хранят снимок имени, типа и сводки в `draft.entities`, поэтому предпросмотр
уже вставленного материала не требует сети. Для поиска новых карточек нужен API
энциклопедии. Неизвестные ссылки отображают пояснение, а не сломанный элемент.
Внешние Markdown-изображения намеренно не загружаются: добавляйте фотографии через
правую панель. Обычные безопасные веб-ссылки доступны.

JPEG, PNG и WebP ограничены 20 МБ и 40 Мп на файл. Оригинал сохраняется без изменений;
поворот, нормализованный crop и цветокоррекция записываются в `image.edits`.
`renderArticleImage(image, maxSize)` возвращает обработанную копию для предпросмотра
или будущей загрузки на сервер. У используемой в тексте фотографии нельзя случайно
удалить запись; замена сохраняет ID и существующие ссылки.

«Обрезать» открывает рамку на полном повёрнутом изображении: перемещайте область
или тяните за её углы и стороны. Можно выбрать фиксированные пропорции либо
«Произвольный кадр». Стрелки уточняют положение/размер, Shift увеличивает шаг;
Escape отменяет незавершённое перетаскивание. «Готово» показывает обрезанный результат.
Изменения кадра записываются после отпускания мыши/касания, а не на каждом кадре
движения. Ползунков кадрирования нет; цветокоррекция использует свои ползунки.

## Серверная интеграция

Публичный контракт черновика — `model/types.ts`. Бэкенду предстоит добавить хранение
статей/изображений, права, модерацию и планировщик. При переносе на сервер нужно
заменить локальные media-идентификаторы на постоянные, загрузить обработанные
изображения и явно подтвердить создание отложенного задания. Существующее поле
`scheduledFor` не является подтверждением серверной отправки.

## Проверки

```sh
npx vitest run --config src/tools/article-editor/vitest.browser.config.ts
npx vitest run --config src/tools/article-editor/vitest.config.ts
```

Полный сценарий маршрута, черновиков, фотографий, карточек, расписания и адаптивности
(изолированный браузер, тестовые API, без серверных записей):

```sh
node scripts/test-article-editor.mjs
```

По умолчанию используется `http://127.0.0.1:5173`; другой сервер задаётся переменной
`ARTICLE_EDITOR_TEST_URL`. Снимок страницы сохраняется во временный каталог ОС.
