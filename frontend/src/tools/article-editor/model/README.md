# Локальные статьи

`useArticleDrafts()` открывает последний активный черновик. При первом входе
одна readwrite-транзакция создаёт ровно одну пустую статью, в том числе при
StrictMode и одновременном открытии вкладок. До загрузки `activeDraft = null`.

Данные хранятся в IndexedDB: `drafts` — JSON статьи по `id`, `assets` — исходные
`Blob` по `assetId`, `meta` — последний активный id. База разделена по локально
прочитанному `user_id`/`sub` JWT. Это не серверная авторизация. При отсутствии
идентификатора используется `guest`. Фоновая очередь привязана к исходному
аккаунту даже при выходе из него перед завершением сохранения.

Автосохранение откладывается на 450 мс. Переключение статьи, создание новой,
уход со страницы и скрытие вкладки инициируют немедленный flush. Записи идут
последовательно; правка, пришедшая во время записи, остаётся в очереди. Запись
одной статьи не переписывает список остальных, поэтому соседняя вкладка
не теряет свои другие черновики. Одновременное редактирование **одной и той же**
статьи в разных вкладках пока использует last-write-wins; совместного редактора
и слияния конфликтов нет.

При ошибках/quota форма и очередь не откатываются. `retrySave()` повторяет
запись; `saveState = error`, `error` содержит сообщение. При закрытии страницы
с несохранёнными данными запрашивается стандартное предупреждение браузера.
Незавершённый контроллер удерживается в памяти SPA по исходному аккаунту:
возвращение в редактор после навигации восстанавливает несохранённые правки.
После успешного flush он освобождается; чистые редакторы при новом входе
читают IndexedDB заново. Асинхронную транзакцию и несохранённую память при
принудительном закрытии/перезагрузке браузера гарантировать невозможно.
IndexedDB также может быть очищен самим пользователем/браузером.

`captureImageAssetRepository()` возвращает `{ scope, save(id, blob), get(id) }`.
Аккаунт захватывается при создании репозитория, до асинхронной обработки
изображения. `scope` нужно включать в ключи кешей обработанных фотографий:
одинаковый `assetId` другого аккаунта не должен вернуть чужую копию из памяти.

Удаление черновика подтверждается транзакцией до удаления из памяти. Оно не
удаляет исходные assets: их могут использовать другие статьи. Автоматической
сборки неиспользуемых медиа пока нет. При удалении последней статьи создаётся
один новый пустой черновик.

`scheduledFor` — **только локальная настройка**. Этот модуль не публикует статьи,
не отправляет на модерацию и не реализует серверный таймер.

Проверка на реальном Chromium IndexedDB без дополнительных зависимостей:

```sh
npx vitest run --config src/tools/article-editor/vitest.browser.config.ts src/tools/article-editor/model
```
