# Общее «Популярное»: контракт API

Фронтенд больше не использует личную историю или `visitCount` для рейтинга.
История посещений остаётся локальной и привязанной к аккаунту.

## Чтение рейтинга

`GET /api/encyclopedia/popular/?page_size=20`

Авторизация и доступ — как у остальных эндпоинтов энциклопедии (`IsSiteMember`).
Ответ — обычный пагинированный список:

```json
{
  "count": 1,
  "results": [
    {
      "id": 123,
      "name": "Огненный шар",
      "name_en": "Fireball",
      "entity_type": "spell",
      "slug": "fireball",
      "opens_count": 42
    }
  ]
}
```

Это пример формата, не реальные значения. Поля сущности берутся из существующего
`EntityListSerializer`; `opens_count` — неотрицательное целое число.
Сервер возвращает записи с открытиями в порядке убывания общего счётчика,
при равенстве — стабильный порядок по `id`. Клиент сохраняет порядок ответа.

## Учёт открытий на сервере

Счётчик объединяет открытия карточек всеми пользователями, а не выборку
`request.user`. Он хранится отдельно от содержательных данных `Entity`.
Источником служат успешные обращения к существующему detail API карточки
`GET /api/encyclopedia/<id>/`. Запросы списков, поиска и самого рейтинга не считаются
открытиями. Повторные обращения одного пользователя к одной карточке за короткое
окно (например, 30 секунд) следует дедуплицировать, чтобы загрузки/повторы не
раздували рейтинг. Конкретное окно фиксируется бэкенд-разработчиком.

Увеличение счётчика атомарное; неуспешные/запрещённые обращения не учитываются.
В ответе нет пользовательских идентификаторов и приватных данных. Фронтенд не
передаёт счётчики из localStorage на сервер и не суммирует данные аккаунтов.

## Статус реализации

В текущем Django API этого эндпоинта и серверных счётчиков нет.
Эта итерация реализует только фронтенд и контракт, без изменений `backend/`.
Пока сервер не подключён, панель показывает «Общий рейтинг пока недоступен»
с повтором загрузки. При пустом успешном ответе — «Пока нет данных об открытиях».
