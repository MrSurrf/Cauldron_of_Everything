# Представление существ

Основой оформления остаётся тёмная тема. Светлая тема экспериментальная,
требует значительной доработки и не служит ориентиром для дизайна и разработки
инструментов.

## Компоновка

`CreatureFullView` используется на странице бестиария и в панели стола кампании.
Внутреннее устройство шапки, боевого паспорта, характеристик и инфографики
сопротивлений, иммунитетов и уязвимостей сохраняется. Изменена внешняя компоновка:
описание расположено после игровых разделов, а не в правой колонке. Его объём
не определяет ширину действий. При отсутствии описания и среды обитания отдельный
раздел не выводится. Навигация позволяет перейти к действиям или описанию.

Навыки, иммунитеты к состояниям и языки представлены отдельными группами,
которые переносятся по доступной ширине. `CreatureFeatureSections` задаёт общий
формат для особенностей, действий, бонусных и легендарных действий, реакций,
действий логова и региональных эффектов. Пустые параметры не выводятся. Урон
с формулой можно бросить; фиксированное значение отображается без кнопки броска.

`CreatureSectionContent` выделяет явно подписанные группы заклинаний по частоте
использования или уровню ячейки. Ссылки, ограничения, списки и таблицы сохраняются.
Неизвестный формат остаётся обычным содержимым, без попытки угадать его структуру.

## Правила хранения и редактирования

- При разборе именованных особенностей исходная разметка хранится в
  `descriptionHtml`, вступление — в `introductionHtml`. Из текста извлекаются
  показатели атаки, спасброска, дальности, цели и урона, но полный текст правил
  сохраняется вместе с условиями и исключениями.
- В импортированной способности HTML служит источником правил. На столе
  кампании пользователь редактирует текст; распознанные показатели обновляются
  при выходе из поля. Отдельные поля этих показателей скрыты, чтобы числовые
  значения не расходились с текстом. Нераспознанные правила остаются видимыми.
- Собственные способности без `descriptionHtml` сохраняют независимые
  структурированные поля. Описание и вступление в этом случае поддерживают
  формат общего `ContentEditor` и отображаются через `ContentPreview`.
- Наличие `entries`, включая пустой массив, означает, что используется
  структурированная секция. Исходный `html` служит запасным представлением только
  при отсутствии `entries`. Удаление последней способности не восстанавливает
  старый текст секции.
- Неизвестная структура исходного HTML выводится целиком через `RichContent`.
  Изменения не требуют массовой правки датасета и не исправляют автоматически
  ранее сохранённые пользовательские копии с уже потерянным содержимым.

## Проверка

Из папки `frontend/`:

```sh
npx vitest run --config src/entities/creature/vitest.browser.config.ts
npx vitest run --config vitest.unit.config.ts src/entities/creature/model/creatureRepository.test.ts src/entities/creature/ui/creatureSectionPresentation.test.ts
```

Браузерные проверки покрывают все виды действий, фиксированный урон и броски,
врождённые заклинания, короткое/длинное/отсутствующее описание, узкие панели,
сохранение разметки при редактировании и удаление последней способности.
