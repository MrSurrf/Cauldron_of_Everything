# FormField

Единая структура текстовых полей дизайн-системы. По умолчанию компонент
рендерит однострочный `TextInput`; вариант `as="textarea"` сохраняет переносы,
кастомный скроллбар и остальные возможности `TextArea`.

```tsx
<FormField
  label="Имя персонажа"
  required
/>

<FormField
  as="textarea"
  label="История персонажа"
  maxLength={500}
  rows={8}
  showCharacterCount
/>
```

## Поведение

- `label` находится внутри рамки и работает как визуальная подсказка;
- при фокусе или появлении текста label плавно уменьшается и перемещается к
  верхней границе, не меняя высоту и ширину поля;
- если задан `label`, нативный `placeholder` визуально скрывается, чтобы тексты
  не накладывались друг на друга;
- состояния hover, focus, disabled и error используют токены дизайн-системы;
- новая ошибка сначала запускает короткую shake-анимацию всей рамки, label,
  иконки, счётчика и скроллбара, после чего появляется danger-состояние;
- попытка превысить нативный `maxLength` не добавляет лишний символ, но даёт
  такой же визуальный feedback и один раз за попытку объявляет достижение
  лимита скринридеру; это работает и для усечённой браузером вставки;
- временное danger-состояние лимита снимается после следующего допустимого
  ввода или потери фокуса;
- `disabled` и `readOnly` не запускают shake-анимацию;
- при `prefers-reduced-motion: reduce` анимация отключается;
- `hint` показывается компактной строкой под рамкой;
- `error` заменяет `hint`, окрашивает рамку и label и объявляется скринридером;
- `showCharacterCount` размещает счётчик внутри поля. В `textarea` он находится
  в правом нижнем углу, а внутренние отступы сохраняют место для текста и
  кастомного скроллбара.

Ошибка, присутствующая уже при первом рендере, сразу показывается в
danger-состоянии: компонент не трясёт сразу все невалидные поля при открытии
страницы. Controlled-значение длиннее `maxLength` считается семантической
ошибкой до возвращения в лимит.

## Свойства

- `required` — нативная обязательность и маркер `*` рядом с label;
- `invalid` — ошибочное состояние без обязательного сообщения;
- `showCharacterCount` — количество введённых символов; вместе с `maxLength`
  формат становится `текущее / максимум`;
- `validationKey` — изменяемый ключ попытки валидации; позволяет повторить
  shake для той же внешней ошибки, например после повторной отправки формы;
- `as="textarea"` — многострочный вариант;
- `fieldClassName` — класс внешней структуры с рамкой и пояснением.

Нативные свойства (`value`, `defaultValue`, `onInput`, `onChange`, `disabled`,
`required`, `maxLength`, `aria-*`) передаются соответствующему `input` или
`textarea`. `ref` типизирован по значению `as` и указывает на нативный элемент.
Пользовательский `aria-describedby` объединяется с идентификаторами подсказки,
ошибки и счётчика. Неконтролируемый счётчик синхронизируется после нативного
`form.reset()`.

Внутренний `useFormFieldState` отвечает за controlled/uncontrolled-счётчик,
reset, лимит и последовательность validation-feedback. `TextArea` при этом
остаётся самостоятельным нативным контролом и отвечает только за ввод и
синхронизацию прокрутки. Общие свойства рамки `icon` и `rootClassName`
определены один раз во внутреннем слое `TextField`.

`className` относится к нативному контролу, а `rootClassName` — к его
декоративной рамке. Самостоятельные `TextInput` и `TextArea` сохранены для
низкоуровневых сценариев и обратной совместимости, но поля формы с label и
состояниями следует создавать через `FormField`.
